Ganit · AI as part of the calculator

Design walkthrough · prototype only, no production code touched · Open the click-through prototype →

One operation, four outcomes

Everything below is the same operation — Ask (⌘⇧A). What differs is the shape of the outcome, and the shape decides what the user has to do about it. Read-only outcomes are transient and need nothing. Source-changing outcomes are always a preview and always need Apply. There is no mode switch, no chat thread, no sidebar.

The four UI shapes, and the rule that keeps them out of the way

The answer column is sacred. Only Ganit ever writes an answer there. AI output lives in cards (transient) or in source (permanent). This one rule removes the current wart where a purple AI value sits in the answer column and formulas are told not to use it.
ShapeLooks likeLifetime · identity
Ask barThe Find bar / completion list: one field, one status line, anchored at the caretTransient. Esc or typing dismisses. Only entry point.
Explain / Answer cardThe existing interpretation card, same popover grid styleTransient. Never saved, never referenced, Esc closes.
ProposalA small panel under the affected lines with its own live answer column, +/~ marksTransient until Apply. Apply = one named Undo step.
Assumption lineOrdinary Ganit line + purple AI badge + // AI: … commentPermanent sheet source. Badge + purple dot on dependents.

Provenance is about the origin of a number, not who typed it

AI-written formula structure is verified by Ganit and then belongs to the user — it is not marked, because a permanent "AI wrote this" badge would say distrust this line when Ganit has actually checked it. An AI-supplied value (water density, a typical rent-growth rate) is a number that came from neither the user nor Ganit's arithmetic. That is what gets the badge, permanently, until the user edits it — editing a value makes it the user's number and drops the badge.

Downstream lines that transitively read an assumption get a small purple dot before their answer. Ganit already carries line dependency provenance, so this is derivable, not a new bookkeeping burden. View ▸ Mark AI-derived answers turns the dots off for people who find them noisy; the origin badge never disappears.

Removed: the 1.2-second automatic request. ADR 0012 claims the assistant makes "a request nobody makes without asking for it" — the automatic fallback contradicts that. Ganit now detects locally and offers; text leaves the Mac only on ⏎.

Key product decisions

QuestionDecisionReasoning
Primary invocationOne command: Ask ⌘⇧AContext (caret line / selection / sheet) already says what the target is. Modes would duplicate it.
User types natural language into a lineIt stays prose. Ganit does not auto-send.Markdown Mode makes prose a legitimate first-class line. Auto-sending is a privacy surprise and produces purple answers nobody asked for.
Failed lines auto-offer AI?Offer, never act. Chip on the caret's line only.Keeps the "correct before clever" promise: Ganit's own diagnostic is still the first word.
"Answer/explain" vs "change my calculation"Not asked. The outcome shape distinguishes them.Read-only outcomes are free and transient; anything touching source requires Apply. Guessing wrong is therefore cheap and always one ⌘Z away.
Source vs prose from the modelDefault to source. Prose only when there is nothing to calculate."Once AI helps create a calculation, changing inputs must keep working without AI."
Preview / partial acceptProposal is live-evaluated by Ganit; each line toggleableAnswers in the preview are real answers, not model claims. Per-line opt-out covers the 80% case without a diff editor.
UndoApply is one named step, "Apply AI change", in the sheet's own Undo managerGanit already does named one-step source patches for tables. No AI-specific undo stack.
Validation failureAutomatic repair ≤2 turns, one status line; then an honest failure cardModel retries are plumbing. The failure reason is translated into Ganit's own words (mortgage isn't a Ganit function; Ganit has pmt, fv and pv).
ClarificationThe Ask bar becomes the question; answered in place; original instruction shown as a crumbCompleting an action, not starting a thread. Capped at 2 questions per Ask.
Missing knowledge vs missing intentWorld knows → assumption + badge. Only user knows → question.Keeps AI useful without silently inventing user intent.
Context sentSelection + transitive dependency lines only; sheet-level Ask sends the sheet. Shown in a Context ▸ disclosureExtends the existing per-line privacy discipline to bigger asks, and makes it inspectable instead of implicit.
ask_assistant(prompt)Remove.Non-deterministic source that silently re-asks when inputs change — the direct opposite of "change inputs, recalculate normally", and the least auditable surface. Assumption lines replace it.
Automatic fallbackRemove, replaced by the passive chip.See above. The reply cache survives, narrowed to a per-session request cache for repair cost control.
Answer-column AI valuesRemove. Answer column is Ganit-only.Kills the "AI display answer, which formulas cannot use" error and the two-tier answer concept.

Alternatives considered, and rejected

AlternativeWhy not
Chat sidebarMakes the answer live in a transcript instead of the sheet; permanent chrome; re-asks instead of recalculating.
Two commands ("Explain" / "Change")Users can't reliably pre-classify their intent; the accept step already does the classifying for free.
Apply-on-Type (AI writes directly into the sheet, ⌘Z to undo)Violates "changes should be visible and reviewable"; a wrong insert shifts line numbers, which Ganit's line N references follow silently.
Keep ask_assistant "for power users"Two AI mental models in one product. Anything it can do, an assumption line does deterministically and inspectably.
Send the whole sheet as contextWorst privacy story, weakest-model-unfriendly token cost, and mostly irrelevant context.

Deliberately deferred

  • Inline diff editing of a proposal (per-line opt-out covers most; a real diff editor is its own project).
  • Ask in Quick Ganit, Services, Shortcuts, ganit:// — keep the scratchpad pure; revisit after v1 usage.
  • Multi-turn "make this sheet do X" beyond the 2-question cap; sheet-wide re-modelling; table-block targets (tables stay fully local).
  • Streaming answers and progressive proposals — needs a different Ask bar and buys little on local models.
  • Assumption freshness / provenance lookup (was that density from a paper or from Reddit?) and citation chips.
  • Model routing (a small model for repair, a big one for modelling), per-sheet model choice, cost display.
  • Learning the user's conventions across sheets (their usual tax rate), which needs a durable preferences layer.
  • Undo grouping across many Applies, proposal history, and "undo everything AI did in this sheet".
