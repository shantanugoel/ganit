# 0.5.5 reference integrity verification

- Date: 2026-09-30
- Candidate: 0.5.5 changes based on `cbb4e48`
- Baseline: unchanged archive of `cbb4e48` (0.5.4), built in a temporary directory
- Hardware: MacBookPro18,2, Apple M1 Max, 32 GB
- System: macOS 27.0
- Toolchain: Xcode 27.0
- Configuration: release, arm64

Each editor benchmark ran in its own process with 200 alternating edits. The
baseline and candidate were measured on the same machine and toolchain.

| Fixture | 0.5.4 P50 | 0.5.4 P95 | 0.5.5 P50 | 0.5.5 P95 | Existing target |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1,000-line mixed sheet | 26.017 ms | 28.931 ms | 25.184 ms | 26.592 ms | 16 ms |
| 10,000-line dependency chain | 59.162 ms | 64.329 ms | 59.364 ms | 60.213 ms | 50 ms |

These are single-process percentiles, not five-process medians. As recorded
for 0.5.4, the absolute latency targets are unmet on this system in both the
baseline and candidate. This point release has comparable or lower measured
latency and does not change or certify those targets. Numeric replacements
skip reference scanning; structural edits track surviving source ranges.

Other release-build measurements:

- Parser: 5.246 microseconds per expression over 1,000,000 expressions.
- Resident Quick Ganit: P50 5.068 ms, P95 10.516 ms over 200 shows.

Validation:

- All 541 package tests pass, including storage recovery rehearsals.
- Golden corpus, arithmetic properties, and Unicode/parser fuzz smoke pass
  under Address Sanitizer, including persisted broken-reference diagnostics.
- Double-length localization layout passes, including Release Notes.
- Release app bundle builds and passes `scripts/verify-app.sh`.
- Homebrew's own cask loader accepts the rendered template and verifies the
  quit directive and reopen reminder; no package installation was performed.
- Four preceding nightly fuzz runs passed.
- Live isolated-app checks confirm first-launch Release Notes after the tour and no repeat after restart,
  deletion producing `@deleted`, a dependent error naming its originating
  line, and one Undo restoring the deletion and all reference changes.
- The packaged CLI evaluates compact references and reports broken markers
  and their downstream failures without treating them as values.

Local bundle checks use ad-hoc signatures. Developer ID signing, notarization,
Sparkle appcast signing, publication, and tap updates use the tag-triggered
release workflow and require its successful completion.
